# 常见问题（FAQ）

按"大家真正会问的问题"排，答案都指向代码里的具体机制，方便你自己去核。

## 我同时用 Claude Code 和别的 agent，它们能共享历史吗？

能，这是本项目存在的理由。每个 agent 一种 adapter（DSH / Claude Code / Kimi Code），
把各自目录里的会话挖出来入库，**写入时回填原始时间戳**——否则全部变成"入库时间"，
跨 agent 的时序就是假的（这是踩过才修的坑）。

## 这和把经验写进 `CLAUDE.md` / `AGENTS.md` 有什么不同？

`CLAUDE.md` 是**每次**都塞进上下文的静态文件，写多了就是token 税；
`aml` 是**按阶段检索**：P0 定位只要 6 条 1200 字，P2 动手前只要 3 条 600 字，用完不留。
另外它还能回答"这条是谁说的、什么时候说的"。

## 记忆会不会把过期或错误的东西带进上下文？

这是最该担心的问题，所以设计上有四道：

1. **程序性内容（技能正文）默认不进通用检索** —— 它们是"照做会改变行为"的指令，只该显式加载
2. **复核期**：蒸馏出来的知识带 `review_after`，检索时会标 `⚠已过复核期`
3. **可靠度排序**：被用过且有效的排前面（拉普拉斯平滑，1 次成功 ≠ 满分）；**没数据的记忆不受惩罚**
4. **可测量**：任务级基准里有 `forbidden`（被记忆带偏率）与 `regression`（踩坏既有功能率），
   检索层有 **P@3**（前 3 条里真正相关的比例）——不靠感觉判断"准不准"

## 技能自动更新会不会覆盖我的改动？

不会，有四条闸门（`src/aml/patrol/update.py`）：本地打了补丁的**永不覆盖**；本地指纹变过的**只暂存**；
其余才自动更新；再加一条**能力/生命周期闸门**——上游新版新增了"未声明的高危能力"（shell/密钥/写文件…）时
也只暂存。**采纳必须由人做**（`aml patrol accept`），而且采纳前会给你看能力差异。

## 必须装 mcp-memory-service 吗？

检索和存储要它（HTTP + MCP，本机跑）。`aml` 这层是采集/蒸馏/检索策略/治理/基准。
两者是分开的：你可以只把 `aml` 当 CLI 用，也可以只把它当 MCP server 接给别的客户端。

## 数据存在哪？会上传吗？

默认全在本机 `$AML_HOME`（默认 `~/aml`）：`state/`（运行数据）、`knowledge/`（**人能读的 markdown 镜像**）、
`backups/`。检索用的是本地嵌入模型，不调云端 API。
**例外要说清楚**：`aml distill` 会把会话原文发给 LLM 提炼（这一步是你的 key、你的调用），
目前**没有发送前脱敏层**——这是 ROADMAP 里记着的缺口，别当成已解决。

## 库越来越大怎么办？

`aml denoise`（软删除界面回显/纯确认语这类噪声）、`aml dedup`（近义知识合并，可回滚）、
`review_after` 到期复核、`aml backup`（在线备份，按天保留）。

## 怎么证明它有用？

两把尺子：**检索层基准**（`aml bench`：命中率 / P@3 / 注入量分位数 / 问法对照）与
**任务级基准**（`aml bench --task-level`：真起 agent 跑任务，判成败、算成本、
`--ablate N` 藏掉记忆做反事实）。
诚实版本：我自己的首跑是 3 个任务 × 2 组、**成功率差值 +0%**（$1.79）——
这些任务的做法能从仓库里推出来，记忆没改变成败。详见 [`TASK-BENCH.md`](TASK-BENCH.md)。

## token 会不会被吃爆？

每个阶段有固定预算（P2：3 条 600 字；P1：5 条 1500 字），同阶段同查询 10 分钟内不重查，
基准报告会给 P50/P95/max 而不是只说平均值（平均值会掩盖尾部）。

## 支持哪些 agent？怎么加新的？

DSH（`~/.dsh/sessions/*.jsonl.zstd`）、Claude Code（`~/.claude/projects/**/*.jsonl`，含 subagent）、
Kimi Code。加一个 adapter = 在 `src/aml/adapters/` 下写一个类：`discover()` 返回会话文件、
`turns()` 产出 `(角色, 文本, 时间戳)`，然后在配置里挂上。本机实测 Codex CLI / Copilot Chat /
Cursor **当前没有可用会话数据**，所以没写。

## 它和"另一个 agent memory / RAG 框架"的区别是什么？

三处不一样：① **技能治理**（上游监控 + 能力声明 + 生命周期 + 四条闸门），
这是多数 memory 项目没有的；② **程序性内容与知识分流**（技能正文不自动进上下文）；
③ **可验证**（自带两层基准与反事实臂，而不是只给一张架构图）。
